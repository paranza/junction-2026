# Trace architecture and earlier research proposal

**Implementation status, 14 November 2026:** the runnable application is in
[`stoa-trace/`](../stoa-trace/). It uses FastAPI, React, native PDF/DXF/IFC/SVG
extraction, source-grounded quantity checks, cached visual inventories and
reviewable object evidence. See its README, handoff and measured evaluation
reports for actual capabilities and limits.

The proposal below is retained as research history. CenterNet, SAM 2,
Mask2Former, GNNs and Gemini are **not deployed in Trace**. The percentages and
perfect-extraction language below are hypotheses, not measured results.
Detection and segmentation do not establish object completeness, semantics,
scale or engineering correctness. Counts and measurements require evaluation
against independently checked sources.

## Earlier proposal

The proposed target was high accuracy, low inference cost and visual
verification by separating extraction from language reasoning. No 99%
accuracy result was established for this proposal.

## 1. The Perception Layer (Vision & Math)
This layer runs deterministic, lightweight models to extract geometric truths. 

*   **Vector Data (IFC, DWG, DXF, SVG):**
    *   **Method:** Graph Neural Networks (GNNs) or rule-based parsing.
    *   **Why proposed:** Preserve structured source records where available. Extraction alone does not guarantee correct scope, counts or area semantics.
*   **Raster Data (PDF, PNG, JPEG):**
    *   **Counting:** Use **CenterNet**. It models objects as points rather than bounding boxes. It is theoretically elegant, mathematically clean, and lightning-fast for counting tiny symbols (sinks, toilets).
    *   **Area/Length proposal:** Evaluate **SAM 2 (Segment Anything 2)** or **Mask2Former**. Polygons would still need validated object semantics, scale, units and error measurements.

## 2. The Data Handoff (The JSON Bridge)
The Perception Layer translates all visual and graphical findings into a highly structured, machine-readable format.
*   **Output:** A single `.json` file containing all detected entities, their exact coordinates, classifications, and calculated measurements (e.g., `"room_4": {"type": "bathroom", "area_sqm": 12.5, "toilets": 1}`).

## 3. The Brain Layer (Gemini for NLP & Q&A)
We offload all language and reasoning tasks to the Gemini API. 
*   **The Prompt:** We pass the user's specific query from `questions.jsonl` along with the structured JSON metadata generated in Step 2 into Gemini.
*   **Why:** Gemini does not struggle with pixel math because it doesn't look at the image to count. It reads our deterministic JSON outputs and answers conversationally, fulfilling the NLP requirement with high intelligence and zero local LLM hosting costs.

## 4. Visual Verification (Overlays)
*   **Method:** A lightweight backend script (e.g., Python/FastAPI) takes the exact coordinates generated by CenterNet and SAM 2 in Step 1 and draws them onto the original image.
*   **Result:** Glowing dots for counted objects and semi-transparent colored polygons for area segments. This allows human judges to verify the system's reasoning in less than a second, fulfilling the 25% Visualization criteria.

## Proposed relationship to the judging criteria

Accuracy, visual verification, creativity and low inference cost each carry
25% in the mirrored challenge brief. A proposed architecture cannot establish
winning performance. The implementation must demonstrate correct answers,
usable source evidence and measured costs on unseen drawing groups.
